4. P0 — jab tak yeh fix na hon, asli paisa bilkul nahi
01
Live bot ke paas koi risk control nahi
Critical
live/live_trade_mt5.py  aur  live/live_trade_metaapi.py  mein: koi stop-loss nahi, koi take-profit nahi, daily loss limit nahi, max drawdown check nahi, consecutive-loss breaker nahi, aur  RiskSupervisor  import tak nahi hua. Lot size hardcoded  VOLUME = 0.01 . Agar model ghalat side pakar le, account ko rokne wali koi cheez nahi hai.
02
RiskSupervisor khud buggy hai
Critical
Action index (0/1/2) ko position fraction maan liya gaya hai, is liye har long trade "POSITION_TOO_LARGE" keh kar reject hota hai (maine chala kar verify kiya). Iske ilawa state sirf memory mein hai — process restart hote hi daily loss counter, drawdown aur consecutive losses zero ho jate hain, yani restart karke aap apne hi circuit breaker ko bypass kar dete hain. Correlation rule bhi hardcoded hai (DXY upar ho to long block).
03
Train aur live ke features bilkul match nahi karte
Critical
Training 150+ features (M5 base, multi-timeframe + macro + calendar) par hoti hai, jabke live script  features.make_features.compute_features  se sirf basic features banata hai aur PPO ka  train/ppo_xauusd_latest.zip  load karta hai. Upar se normalization: training mein poore dataset ke mean/std, live mein sirf aakhri 200 bars ke mean/std. Yani live par model ko woh numbers milte hain jin par woh train hi nahi hua — output bekar hoga. Feature schema + scaler ko model ke sath save karna lazmi hai.
04
Look-ahead bias (future ka data leak)
Critical
Teen alag jagah:
Multi-timeframe   resample  bar ko uske  shuru  ke waqt par label karta hai, phir H1/H4/D1 features ko M5 par  ffill  kar diya jata hai. Matlab 10:00 wale M5 bar ko us H1 candle ka close mil raha hai jo 11:00 par band hoga — yeh future ka data hai.
Macro daily  DXY/SPX/VIX ka daily close 00:00 par stamp ho kar poore din mein ffill hota hai, yani din ke shuru mein hi us din ka close pata chal jata hai.
Normalization   features/make_features.py  poore dataset (train+test) ke mean/std se normalize karta hai — test period ke statistics train mein leak ho jate hain.
Isi wajah se koi bhi purana backtest result ya "Sharpe 3.5+" wala claim abhi qabil-e-aitbaar nahi hai. Feature layer theek karne ke baad sab kuch dobara train aur evaluate karna hoga.
05
Backtester asal mein backtest karta hi nahi
Critical
backtest/backtest_engine.py  ka  _get_observation()   np.random.randn(100)  return karta hai, aur  walk_forward_validation()  mein training line comment ki hui hai ( # self.agent.train(train_data) ). Naam "RigorousBacktester" hai lekin natija random noise par bana hota hai.  eval/crisis_validation.py  bhi placeholder P&L aur MockAgent par khara hai.
06
Execution loop galat hai
Critical
10 second loop  H1 strategy hote hue bhi loop har 10 second chalta hai — ek hi candle par 360 dafa faisla, adhi-bani candle par. "Candle band hone" ka gate nahi hai.
Adhura candle  MT5 se aane wala aakhri bar abhi mukammal nahi hota, lekin usi par decision ho raha hai.
Sirf long/flat  Live mein short bilkul nahi, jabke Dreamer env  allow_short=True  ke sath train hota hai.
Order result  MT5 retcode ki poori checking, retry, partial fill aur requote handling nahi. Idempotency (duplicate order se bachao) nahi.
Reconciliation  Broker par asal position aur bot ki soch ko match karne wala koi code nahi. Restart ke baad bot ko pata nahi hota usne pehle kya kiya tha.
07

8. Roadmap — kis tarteeb se complete karna hai
P0
Safety aur correctness (pehle yeh)
1–2 hafte kaam
Live trading ko abhi ke liye  demo-only  lock karein: ek env flag  TRADING_MODE=demo|live , aur live mode tab tak error de jab tak sab gates pass na hon.
RiskSupervisor  ka position-size bug fix karein (action ≠ size), state ko disk/SQLite par persist karein, aur usay dono live scripts mein har order se pehle lazmi banayein.
Feature contract banayein: training ke waqt  feature_names  + scaler (mean/std)  scaler.json  mein save, live par wahi load. Mismatch par bot start hi na ho.
Look-ahead fix: higher timeframe features ko ek bar  shift(1)  karein (ya  label='right', closed='right'  se resample karein), macro daily ko bhi shift karein, aur normalization sirf train window par fit karein.
Live loop theek karein: sirf band hui candle par decision, candle-aligned sleep, duplicate-order guard (client order id), SL/TP har order ke sath, order result ki poori checking + retry.
Startup par broker se position reconcile karein; local state aur broker state alag hon to trade band aur alert.
Dono live scripts ko ek hi core mein merge karein (strategy + risk + execution alag layers, broker adapter interchangeable).
metaapi_cloud_sdk  requirements mein add karein aur versions pin karein.
P1
Sach bolne wala evaluation aur operations
2–3 hafte kaam
Backtester dobara likhein — placeholder observations hata kar wahi  RealisticTradingEnv  aur wahi feature pipeline use karein jo training mein hai.
Walk-forward validation asal mein chalayein (train → validate → test, purge/embargo ke sath), aur baselines (buy&hold, random, simple MA) ke against compare karein.
Crisis validation ko asal agent + asal env par chalayein, MockAgent hatayein.
Model registry + promotion gate: checkpoint ke sath metrics, data range, feature hash, git commit; sirf gate pass model hi live ja sake.
Observability: structured logs, har trade ka audit record, equity/drawdown metrics, heartbeat, Telegram/email alerts, aur ek manual kill switch file/flag.
Deployment: Dockerfile + systemd unit + GitHub Actions (lint, tests) — abhi teeno mein se kuch bhi nahi.
Tests barhayein: risk supervisor, feature causality, execution adapter (mock broker), reconciliation.
P2
Alpha aur scale (sirf P0/P1 ke baad)
Baad mein
Kelly sizing ko theek kar ke dynamic lot size (abhi fix 0.01).
Ensemble / MCTS / Transformer / MAML ko orchestrator mein jorna — pehle backtest mein sabit karein ke faida deti hain.
Asal economic calendar API (actual vs forecast, DST-aware) aur asal sentiment feed.
.kiro wala AutonomousOrchestrator banana, regime detection ke sath.
Dashboard, multi-symbol, hyperparameter search.
